# Detection 009 – Privileged Domain Group Membership

## Objective

Detect accounts added to privileged Active Directory global groups by monitoring Windows Security Event ID 4728. Attackers may modify group membership to gain administrative control, maintain persistence, or expand access across the domain.

---

## MITRE ATT&CK

| Tactic | Technique |
|---|---|
| Persistence, Privilege Escalation | T1098 – Account Manipulation |

---

## Data Source

- Windows Security Event Log
- Event ID 4728
- Active Directory domain controllers

---

## Detection Logic

Monitor Event ID 4728 and extract the initiating account, added member, and destination group. Focus on privileged groups such as Domain Admins, Enterprise Admins, Schema Admins, and Group Policy Creator Owners.

---

## Splunk Search

```spl
source="WinEventLog:Security" EventCode=4728
| rex field=Message "Subject:\s+Security ID:[^\r\n]+\s+Account Name:\s+(?<AddedBy>[^\r\n]+)"
| rex field=Message "Member:\s+Security ID:[^\r\n]+\s+Account Name:\s+(?<MemberName>[^\r\n]+)"
| rex field=Message "Group:\s+Security ID:[^\r\n]+\s+Group Name:\s+(?<GroupName>[^\r\n]+)"
| search GroupName="Domain Admins" OR GroupName="Enterprise Admins" OR GroupName="Schema Admins" OR GroupName="Group Policy Creator Owners"
| table _time host AddedBy MemberName GroupName
| sort -_time
```

---

## Validation Procedure

1. Search historical Event ID 4728 events on the domain controllers.
2. Extract the initiating account, added member, and group name.
3. Filter results to high-impact privileged domain groups.
4. Confirm the event identifies the affected account and destination group.
5. Preserve the search results and screenshot as validation evidence.

No additional privileged account was created for this test because valid historical evidence was already available.

---

## Validated Result

The detection was validated in the Enterprise Splunk SOC Lab with the following observed values:

- Event ID: 4728
- Host: DC01
- Added member: `CN=Administrator,CN=Users,DC=CANNON,DC=com`
- Privileged groups observed:
  - Domain Admins
  - Group Policy Creator Owners

---

## Investigation Guidance

1. Confirm whether the membership change was authorized and associated with an approved request.
2. Identify the initiating account and the system where the change originated.
3. Review the added member’s recent logons, account changes, and privilege use.
4. Check whether the member was added to multiple privileged groups or whether other accounts were changed nearby.
5. Correlate with PowerShell, process creation, remote administration, and authentication activity.
6. Remove unauthorized membership, secure the affected accounts, and escalate the incident.

---

## False Positives

Legitimate Event ID 4728 activity may be generated by:

- Approved administrator provisioning
- Emergency access procedures
- Role changes and access reviews
- Domain deployment and initial configuration
- Authorized identity-management automation

Reduce noise by baselining approved administrators, privileged groups, change windows, and ticketed access workflows.
